# v5.2 — handoff

Forked from `v5.1-paper` (`cp -R`). `v5.1-paper/` is untouched and remains the fallback.
Everything below lives in `v5.2-paper/`; `windows.html` and `research-toolbar.js` are the
only two files with logic in them.

Run it: the project is served by a plain static server on :3400
(`.claude/launch.json` → `python3 -m http.server`). Useful URLs:

- `windows.html` — the whole flow from the notification
- `windows.html?skip=call` — drop straight into the call with the toolbar up
- `windows.html?dev=1` — variant chip

Design source is Figma `2VEi35TX4R0xj9zLTfFHxo`; node ids are noted per section.
Every geometry figure below was measured in the browser against the node, not eyeballed.

## 1. Notification (632:8691, 633:8714)

442 × 187 card, radius 24. The Dismiss pill is gone — a circular X sits top-right and
widens on hover into a `Snooze (5m)` chip (33 → 128.25px, the Figma width). "Prepare
session" became a full-width dark **Review script** pill carrying the attached doc row.

Hovering the doc row paints a `rgba(45,45,45,0)` → `#2d2d2d` gradient and shows a

Structural note: a nested `<button>` can't express two targets, so `.prepare` is a
container — an absolutely-positioned `#prepare` button fills the pill, `.prepare-body`
sits above it with `pointer-events: none`, and the doc row re-enables them.

## 5. Floating card — the default (641:8964)

476 × 445. 93px header: drag handle, "Ria will take notes · 00:34", "Research Script",
the doc name in 10px thin uppercase, a green Recording indicator, the presence switch.
Footer: scrim, edit chip bottom-left, ←/→ bottom-right, centred **Start Recording** pill.

The body is **the script as a document** — a line-number gutter (I, 1–5), an `#f6f5ef`
highlight on the active section, a custom scrollbar thumb. ←/→ move between sections.

Scoping decision: the document is the PRE-RECORDING body. Once recording starts the
existing question list takes over, because it carries the notes, probes, rewrites, undo
and insight counting the scripted session runs on. The new header and card size persist
into that state; the edit chip and section arrows don't.

## 6. Mini command bar (622:6727)

322.402px in the design; **387px as built** — see the open question below.

Header: pulsing green status, `3. University & Social Life (1/4)`, presence switch.
Body: `1.2`-style number plus one part of the script. Footer: scrim and ↓/↑.

Both surfaces read ONE script model built off the document, so they cannot drift:
sections come from the document's passages, each section's paragraphs and list items
become its parts. Parts run past a section boundary into the next one.

The intro's gutter marker is `I`, which is non-numeric, so that section is treated as
unnumbered: no `I.` prefix on the title, and its parts count `1`, `2`.

## Gotchas that cost time

- **The static server serves stale JS.** `research-toolbar.js` gets cached hard; a plain
  reload keeps the old copy and edits appear not to work. Force it with
  `fetch('research-toolbar.js', {cache:'reload'})` before reloading.
- **The toolbar persists its size and presence mode in localStorage.** A card resized in
  an earlier build overrides the new defaults — 473 × 513 instead of 476 × 445. Clear
  storage when checking dimensions.
- **Arrow keys were already bound.** `research-toolbar.js` binds ArrowRight (start /
  advance) and ArrowDown/Up (questions). The document and the mini bar claim theirs in
  the CAPTURE phase and `stopPropagation()`, so registration order doesn't matter.
- **v5.1 rules sit later in the stylesheet** than the v5.2 block and win on equal
  specificity. `.toolbar-foot` and `.start-rec` had to be deleted outright. Check for a
  later duplicate before assuming a new rule is wrong.
- **`requestAnimationFrame` doesn't run in a background tab**, which made the onboarding
  entrance intermittently never fire. Nothing in the open path depends on rAF now.
- **The project sits under ~/Desktop**, a macOS TCC-protected folder. File access was
  revoked mid-session once; every read returned EPERM while `stat` still worked. Fix is
  Privacy & Security → Files and Folders → Claude → Desktop, then a full quit. Moving the
  project to `~/Projects` would avoid it entirely.

## Open questions

1. **Rae vs Ria.** The onboarding and the new toolbar header say *Ria* and build the
   subtitle around it as an acronym. The toolbar's own copy, the preflight card and the
   insight doc still say *Rae*. Not reconciled.
2. **The session state runs the old script.** The floating card's document shows the
   Kingston interview; the question list underneath still shows "Introduction / Tell me
   about yourself / 18 questions in all" from `SCRIPTS` in `research-toolbar.js`. Visible
   side by side on the canvas. Porting it means authoring new per-question notes, quotes
   and probes — the scripted session story is content, not just data.
3. **Three different session counts.** Previewer header says "5 sections · 25 questions";
   its own body has 4 numbered sections and 15 questions; the preflight card reads
   "5 sections · 18 questions" from `loadedScript`.
4. **Mini bar is 387px, the design says 322.402.** Showing section titles in full does not
   fit the design width alongside the counter and the presence switch. Options: shorten
   the section names, drop the title size, or move the counter to a second line.
5. **Snooze doesn't snooze** — the X says "Snooze (5m)" but dismisses permanently.
6. **"Waiting for attendee" is permanent** — the call stage never switches to Sarah Chen,
   though the scripted session has her answering from the moment recording starts.
7. **Onboarding state 1 has dots and a Next** that the design didn't show; without them
   there's no way forward from it.
8. **Compact can no longer finish a session** — the Finish button was dropped per the
   design. Finishing needs a trip back to focus or dock.
